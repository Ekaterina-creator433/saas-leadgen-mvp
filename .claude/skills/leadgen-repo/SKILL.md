# Скилл работы с репозиторием saas-leadgen-mvp

Демо-лендинг производителя спецодежды ООО «Славянка Текстиль» с формой заявки
и уведомлениями в Telegram. Первый шаг плана развития SaaS «конструктор
мини-лендингов с заявками в Telegram».

## 1. Структура репозитория

```
saas-leadgen-mvp/
├── server.js          # Express-сервер: раздача статики + приём заявок
├── generate-doc.js    # Генерация документов (КП)
├── generate-tz.js     # Генерация ТЗ
├── package.json       # Зависимости и скрипты
├── public/            # Лендинг
│   ├── index.html     # Разметка (hero, продукция, шаги, форма #leadForm)
│   ├── style.css      # Стили (адаптивные grid-сетки auto-fit)
│   └── script.js      # Отправка формы на сервер
├── .env.example       # TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID
└── README.md          # Описание проекта
```

Порт **3000**. Контент лендинга основан на презентации компании:
с 1991 года, 200 000+ комплектов/год, реестр Минпромторга РФ,
г. Владимир, ул. Электрозаводская, д. 1.

## 2. Запуск сервиса

```bash
npm install
npm start        # http://localhost:3000
```

Без заполнённого `.env` заявка не уходит в Telegram, но сервер пишет её
в консоль и возвращает `{ ok: true }` — удобно для тестов.

## 3. Внесение изменений

- **Тексты и блоки лендинга** — правь `public/index.html`; сетки
  `.cards`, `.about__grid`, `.steps__row` адаптивные (auto-fit), количество
  карточек можно менять свободно.
- **Стили** — цветовые переменные в начале `public/style.css`.
- **Форма** — поля формы обрабатываются в `public/script.js` и `server.js`;
  при добавлении поля обнови оба места.
- Контент должен соответствовать данным компании из официальной презентации.

## 4. Обновление README.md

Структура README: название → скриншот → описание → проблема → пользователи →
стек → запуск → настройка Telegram → деплой → проверка без Telegram.
При изменении функциональности синхронизируй разделы «Запуск» и «Стек».

## 5. Проверка ошибок

```bash
node --check server.js     # синтаксис
node --check generate-doc.js
node --check generate-tz.js
npm audit                  # уязвимости зависимостей
```

Функциональная проверка: открыть http://localhost:3000, отправить форму —
в консоли сервера должна появиться заявка и `{ ok: true }`.

## 6. Подготовка к публикации

1. Убедись, что в git не попадают: `.env`, `node_modules/` (уже в `.gitignore`).
2. Не публикуй токен Telegram-бота ни в коде, ни в README.
3. Коммиты: короткое сообщение на английском в императиве.
4. Пуш в `origin main`: `git push origin main`.
5. Репозиторий: github.com/Ekaterina-creator433/saas-leadgen-mvp
